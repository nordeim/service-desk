# ServiceDesk — IT Support Portal

Full-stack IT ticketing portal (Next.js 16 App Router standalone · React 19 · TypeScript strict · Tailwind CSS v4 CSS-first · shadcn/ui · Prisma 6 + SQLite · Vitest + Playwright). A visual-parity, feature-superset clone of the base44 ServiceDesk reference app, maintained as a single deployable process with zero external services.

**Verification gate (must be green before any commit):** `bun run lint && bun run typecheck && bun run test && bun run build` — plus `bun run test:e2e` (198 specs against the production standalone build) when UI/auth behavior changes. **Re-run the gate after EVERY file that lands — including one-off scripts** (a post-gate `.cjs` script broke CI on main in session 7; an inert screenshot-script guard shipped in s12 because nobody executed its failure path). CI (`.github/workflows/ci.yml`) runs the same gate on every push/PR to main — and its badge is a live signal (session 18 found it red on the s17 push: a pin that passed locally only under an ambient :3000 listener; check the badge when a push lands).

## Foundational Principles

### Meticulous Approach (Six-Phase Workflow)

1. **ANALYZE** — Read the relevant page/component/route and its tests in full before writing. Identify which contract (db-path, validation, auth session, UI parity) governs the change.
2. **PLAN** — State the smallest correct path; name the files touched and the specs that must be updated alongside.
3. **VALIDATE** — Confirm scope for anything touching auth, sessions, or the ticket vocabulary before coding.
4. **IMPLEMENT** — Modular, typed, test-backed increments. Domain rules go in `src/lib/` seams; UI consumes them.
5. **VERIFY** — Run the full gate; for visual changes, capture a screenshot and compare against `docs/screenshots/` and the reference captures.
6. **DELIVER** — Report what was verified, what was not, and any deferred debt. Never claim "works" without executed evidence.

### Project-Specific Principles

- **Visual parity is a contract.** The reference app's design was measured (computed styles + DOM classes), not guessed — sidebar `#fafafa`, the cyan→blue gradient motif, badge colors + lowercase badge text, the stacked dashboard layout, `text-4xl` page headings, gradient quick-stats rows, the flat divide-y recent list (FileText tiles, arrows, date-only dates), the detail grid, the login card shell, and the rise-in entrance animations are pinned by E2E specs (`visual-parity.spec.ts`, sessions 2–3). Style changes need a parity reason.
- **Superset, not divergence.** Additions (signup, forgot-password, attachments, owner status control, sort/scope) must not alter reference-visible structure. The reference's own quirks (header inside `<main>`, focus-to-body on sheet close, no nav highlight at `/`) are preserved or deliberately improved (the `/`→`/dashboard` redirect) — document any intentional divergence.
- **Zero third-party auth dependency.** HMAC cookie sessions + scrypt hashing in `src/lib/auth.ts` — auditable, unit-tested, no supply-chain surface. Do not swap in an auth library casually.
- **The database path is load-bearing.** `file:../db/custom.db` anchors against `prisma/schema.prisma`; `src/lib/db-path.ts` replicates the CLI rule at runtime so dev, build, and the standalone server open ONE file. Pinned by 15 tests.

## Implementation Standards

### TypeScript (strict, enforced)

- `strict: true`; no `any` in new code (use `unknown` + guards). Type-only imports stay inline (`import type`).
- Validated-string enums: the ticket vocabulary (categories/priorities/statuses) lives in `src/lib/constants.ts` with type guards — single source of truth for API, UI, and tests.
- Early returns; no deeply nested conditionals; domain guards in `src/lib/validation.ts` return `{ ok, errors }` records the UI maps onto fields.

### React 19 / Next.js 16

- Server Components by default; `"use client"` only for interactive leaves. Authenticated pages live under `src/app/(app)/` — the group layout guards the session server-side (`redirect("/login")`), so pages never re-check. Session 19 split the gate: `src/proxy.ts` (Next 16's middleware successor) checks cookie PRESENCE on the four `(app)` routes and decorates the cookie-less bounce with `?from_url=<absolute url>` (the reference's deep-link contract); the layout remains the AUTHORITATIVE verifier (HMAC) — keep that split (the proxy never resolves sessions; ADR-001's rejection was about duplicating resolution, and `safeRedirectTarget` in `src/lib/redirect.ts` validates the target at use time — same-origin, auth-pages rejected, `/dashboard` fallback).
- `cookies()`, `params`, `searchParams` are **async** — always `await` them.
- Page files export only `default` + `metadata`/`generateMetadata`/`revalidate`/`dynamic`.
- `react-hooks/set-state-in-effect` is an ERROR: external-store state (media queries) uses `useSyncExternalStore` (`src/hooks/use-mobile.ts`), never effect-body setState.
- Client data fetching happens in effects with cancellation (`AbortController`, `cancelled` flags) — pages are hydratable islands over the server shell.

### Tailwind CSS v4 (CSS-first — no config file)

- Semantic tokens: `@theme inline { --color-*: var(--*) }` in `src/app/globals.css`. The `inline` keyword is mandatory — a bare `@theme` with `var()` chains is dropped by the build.
- Variant utilities outrank plain utilities in the cascade (order-independent). This is why the active nav item uses `text-white!` — a plain `text-white` loses to `data-[active=true]:text-sidebar-accent-foreground`. If you override a variant-styled primitive, use the `!` modifier and say why in a comment.
- Design tokens (`--navy-950`, `--cyan-500`, `--amber-500`…) mirror the reference app's `:root` block — keep the `:root` palette literal hex and in sync with the `.dark` block.
- **Font: the system stack, no webfont** (session 5). The reference loads no webfont; `--font-sans` is pinned in `@theme inline` to the reference's computed stack (`ui-sans-serif, system-ui, …` — Tailwind 4.3's default is a different string). Do NOT reintroduce next/font Inter or `antialiased`.
- **Radius scale: Tailwind v3 defaults** (session 6, superseded in 7): `--radius-md/lg/xl` are pinned to 0.375/0.5/0.75rem; `--radius-sm` is 0.25rem (4px — the reference's own rounded-sm re-measured at 4px in session 7; only rounded-sm differs between the v3 and v4 scales). Do NOT reintroduce the calc chain.
- **The accent pair is gray + near-black, not cyan** (session 7): `--accent: #f5f5f5`, `--accent-foreground: #171717` (the reference's stock shadcn pair). It drives select-option highlights, ghost/outline hover text, and the Skeleton. Do NOT tint it cyan — the cyan motif lives in explicit utilities.
- **Hover variants are media-guarded in v4** (`@media (hover:hover)`): on touch devices our hovers are inert while the reference's v3 hovers still apply — an intentional documented divergence. Hover E2E assertions must run under Playwright's Desktop Chrome (hover:hover); agent-browser reports hover:none and reads at-rest values.
- **Focus states are part of parity** (session 6): the Button/Input/Textarea bases use `focus-visible:outline-none focus-visible:ring-1 focus-visible:ring-ring` (near-black `--ring: #0a0a0a`); the SelectTrigger base uses plain `focus:ring-1`. Do NOT restore the new-gen `ring-[3px] ring-ring/50` tail. The reference's cyan focus customs are inert on text inputs, active on selects + the textarea border — see AGENTS.md session-6 contracts. **Raw `<button>`s need the tail spelled out per call site** (session 8: sign-out + attachment Remove).
- **The button cursor preflight is restored** (session 9): Tailwind v4 dropped v3's `button, [role="button"] { cursor: pointer }` preflight; `@layer base` in globals.css carries the rule verbatim (the reference's v3 build renders the hand cursor on every true button). Do NOT remove it.
- **The `:root` block is verbatim STOCK shadcn** (session 9, full token diff): `--primary #171717` (near-black — badge hovers go dark, never cyan), `--border`/`--input #e5e5e5` (neutral-200, not slate-200), `--foreground`/`--card-foreground`/`--popover-foreground #0a0a0a`, `--sidebar-ring #3b82f6` (blue-500, not cyan), `--background #ffffff`. The cyan→blue motif lives ONLY in explicit utilities. Do NOT re-tint the semantic tokens.
- **The Badge atom is the OLD shadcn generation** (session 9): base = `inline-flex items-center rounded-md border px-2.5 py-0.5 text-xs font-semibold transition-colors focus:outline-none focus:ring-2 focus:ring-ring focus:ring-offset-2` + `/80` variant hovers — NOT the new-gen `transition-[color,box-shadow]`/`ring-[3px]` base (the visible delta: hover backgrounds must FADE, not snap).
- **The desktop sidebar edge is `border-slate-200/60`** (session 9, translucent) and the mobile sheet overlay is 80% black (session 8, live-measured). **`min-w-0` on the SidebarInset main is load-bearing** — it kills a mobile horizontal-overflow defect the reference itself has; without it the recent-card rows' intrinsic nowrap width widens the whole document at 375px.
- **Auth error alerts** (session 8): `text-sm text-red-700 bg-red-50/70 border border-red-200 rounded-xl p-4` on `p[role=alert]` — the reference's measured shadcn-Alert contract (was red-600/rounded-lg/px-3 py-2/opaque).

### Data Layer (Prisma + SQLite)

- Schema in `prisma/schema.prisma`; the client singleton in `src/lib/db.ts` resolves `DATABASE_URL` through `db-path.ts` BEFORE instantiating Prisma — never import `@prisma/client` directly in app code.
- npm scripts pin `DATABASE_URL='file:../db/custom.db'` inline — an ambient env var (sandbox default) would otherwise override `.env`. Keep the pin when editing scripts.
- Mutations are route handlers under `src/app/api/**` returning JSON; the comment route updates the ticket's `updatedAt` in one transaction. Never introduce raw SQL with user input; all queries go through Prisma.

## Error Handling & Debugging

- Route handlers return typed JSON errors (`{ error, errors? }`) with correct status codes (401/403/400/404/429); the UI renders field errors inline and surfaces toasts for flow outcomes.
- Unexpected server errors are logged with context (`[auth]`, `[health]` prefixes) — never silently swallowed.
- Debug toolkit: `dev.log` for the dev server; Playwright traces live in `test-results/` on failure; `scripts/probe-gradients.mjs` + `gradient-test*.mjs` reproduce the Tailwind v4 `lab()`/oklab gradient rendering questions (they also document the Next dev-overlay false positive — a fixed dark circle at bottom-left in dev screenshots only).

|---|---|---|
| `DATABASE_URL` | SQLite path, relative to `prisma/schema.prisma` | `file:../db/custom.db` |

## Anti-Patterns to Avoid

- **A mutation battery's mutations are contracts too — each must bite EXACTLY ONE invariant, and the designed bite must be the FIRST thing that fires (session 63: the worklog battery's dup mutation was first shaped as a RENUMBER — creating a hole AND a duplicate, so the pin named the hole class instead of the no-dup invariant — and breaking its own revert (two identical strings after the apply; a string-replace revert cannot distinguish them — the backup-restore form is the cure, the s62 binary-mutation lineage applied to text); the helper-neutering mutation forced the REPORT field the structure check also reads, so the separator/entry mismatch fired before the designed floor. The pure forms — the block-append exact-dup (the last entry block duplicated in full, nothing else changes) and the empty-corpus neuter (the line source forced to `[]`: zero entries AND zero separators, every upstream check passing vacuously) — make the pin's failure message a proof, not an accident.**

- **The parity-evidence surface is a contract surface — an evidence artifact family cited every session needs asset-truth + count + enumeration pins (session 62: the 10-shot screenshots set passed every gate unvalidated while its PAD/AGENTS counts drifted stale — a corrupted PNG, a deleted member, and a 7-vs-10 claim all stood unguarded; the closure extends the s17/s18 magic-byte doctrine with the standing helper + the spawnSync pin) — and a sed-derived battery is a generation like any other: CASE-SENSITIVE patterns miss lowercase path references (the s62 roundtrip called the old s61 cleanup; the s60 lesson-114 lineage class at the reference level).**

- **A scripts-integrity contract that protects one language of a multi-language corpus is a contract with a hole — the static-integrity layer must cover every language the corpus carries, at each language's standard static layer (session 61: the s60 closure scanned the `.py` family only — 83 of 358 scripts — while the battery's per-session entry points are 8 parts `.sh`/`.mjs`/`.ts` to 3 parts `.py`; a syntax-broken shell script or a type-broken `.ts` shipped green and would fail only at invocation, the s12 inert-guard lesson at the language level; the closure: the standing helper `scripts/check-syntax.py` — `bash -n`/`node --check`/ONE tsc invocation — plus the per-language floors 120/115/15; and a slower pin that pushes a nested run past the test runner's 5s default clock is a NESTED-RUN defect, never a timeout — raise the test timeout to the subprocess bound; the operator-transcript recurrence confirmed the fifth consecutive time — the response bound the next session's baseline gate)
- **The operator's transcript archive is inside every pin's sweep corpus — and a count floor guards mass deletion, never the hole (session 57: the operator's session_102.md transcript quotes reintroduced the s56 fabricated-token grammar form; the artifact-existence pin caught it in CI run #153 — 39s, the first red main-branch run ever — and the red state sat between sessions until the next baseline gate; the fix is the de-grammar edit, the first operator-side doc edit: the claim word-form goes, the narrative stays. The deeper slack: the numbered families' COUNT floors pass with a hole in the middle (56 plans, floor 55, one deletion: 55 >= 55) — closed by the exact-set enumeration + the contiguity/one-session-lag floor + the 2N−11 pairing correspondence, born-green, the corpus measured complete. The doctrine: the baseline gate is the operator-side drift catcher — the first duty each session; the doc corpus' indexed families are sequences, not bags — audit the numbering the way the counts are audited; and the head-identification check is multi-reference-sensitive — a single-site title mislabel does not bite, the numbering note's second reference still identifies the doc)**
- **A backticked path-shaped reference in a core doc is an existence claim about the fs — and the operator's transcript recurrence is a standing per-session reality (session 58: the operator's `2914125` transcript commit reintroduced the backticked fabricated-token form at session_104.md:10+12; CI run #156 FAILED in 41s — the second red main-branch run; the fix the de-grammar edit, the third operator-side doc edit. The deeper closure: the s56 scripts-grammar existence-claim class extended to the WHOLE-PATH form — every backticked path-shaped reference in the five core docs held to the fs, born-green (516 checked, all resolving; the four-entry measured exclusion set — the runtime-target + transient + replaced-static forms — each needed-ness-guarded; the floor 500 guards the vacuous pass). The doctrine: the baseline gate is the operator-side drift catcher — the first duty each session, and every session should EXPECT the recurrence; a battery's fill and check strings must name the SAME session — the s57 roundtrip's one-session-lag bug read as a timing artifact and cost a recheck)**
- **A generated lineage script must be validated against its own vocabulary — a blind `.replace()` generation is a stale-name propagator (session 60: the committed s58/s59 wave-analysis scripts' line 24 both referenced `s56_b`, a variable defined nowhere in their files — the make-battery generators replaced only their own session-pair names, and the s56-era leftover survived every generation; the scripts crashed with NameError the moment their /tmp inputs existed, and the recorded wave figures came from in-flight-fixed copies that never landed — a durability gap masquerading as an environment gap at fresh-clone time. The fix: the two one-word lineage edits + the standing AST undefined-name checker + the scripts-integrity pins (the undefined-name check, the scanned-files floor 70, the wave-analysis family floor 4). The doctrine: every battery-generated script gets a post-generation integrity check — the generation's own replace vocabulary is NEVER exhaustive over the file's variables; and the operator-transcript recurrence is now four cycles deep (#153, #156, #159, #162 — the alternating-red pattern): the baseline gate opens every session EXPECTING it)**
- **A match-scoped exclusion must NEVER be implemented as a line-level escape (session 59: the s56 artifact-existence pin 3's `return` inside the `forEach` line callback silently dropped every hex token after the first excluded one on the same line — the operator's line-13 quote co-located with the pure-digit `2914125` escaped the sweep that caught line 52; CI run #159 FAILED, the third red main run, the alternating-red pattern #153/#156/#159. The fix: `continue` in the match loop — the exclusion skips the TOKEN, never the rest of the line. The guard: the no-silent-skip parity pin — every bare-hex token is either excluded or claimed, the raw stream independently re-derived, a dropped token fails naming its file+line; the co-location shape floor 20 (29 measured). The doctrine: an exclusion's SCOPE must match its SEMANTICS, and the mutation battery must try the CO-LOCATED shape whenever the grammar is token-scoped — the single-token mutation verifies the happy path, the co-located mutation verifies the loop discipline)**
- **An existence claim is a claim, and its ground truth is the fs/git artifact it names (session 56: three pre-s42 "persisted `scripts/…`" claims named scripts that were never in git — the workspace resets destroyed the only copies 15+ sessions earlier; the how-to doc cited a push range from the pre-import history the repo's web-upload root makes unreachable; 616 bare commit citations held clean by the exact known-non-commit exclusion set. The class survived because the EXISTENCE shape matches no pin family's form — counts/dates/sizes/source-maps/checkboxes never ask whether a NAMED artifact is real. The closure: the persistence grammar (fs), the range reachability (one batched `git cat-file --batch-check` call, the pre-import annotation the narrow escape), and the bare-citation reachability with the needed-ness guard (every exclusion literal must remain genuinely cited). The harness trap: `--batch-check` returns short-hash inputs EXPANDED to full 40-char forms — key the map by the REQUESTED hash via order-zipping, never by the output's first token. The doctrine: audit the docs' EVIDENCE surfaces — named scripts, cited commits — the way corpus figures are audited against the run; a named artifact that does not exist is a false claim no corpus family will ever catch)**
- **A status claim is a claim, and its ground truth is the checkbox-vs-state relation (session 55: the remediation plans' execution-status sections drifted twice — the s38 "— complete, recorded" text under an UNCHECKED box (a self-contradiction within one line, born at the remediation commit, missed by the closeout that checked only the push box), and the s54 push box honestly unchecked at the remediation commit (the chicken-and-egg: the push of that very commit had not happened) with the closeout updating only worklog.md — the box contradicting the verified pushes + CI-green history. Invisible to every pin family: counts, dates, sizes, and source-maps never ask whether a checkbox agrees with the state it asserts. The closure is three-sided: the closed-plans sweep (every plan below the current session fully checked — the constant bumps each session, so a forgotten closeout fails the VERY NEXT session, naming file + line), the self-contradiction guard (an unchecked box whose own text asserts completion, caught the MOMENT it is written — case-insensitive, the CI-status "COMPLETED/SUCCESS" form included), and the enumeration (glob-driven walk + floor + the current plan present). The push chicken-and-egg is closed BY CONVENTION: the deferral form at the remediation commit ("— see the worklog's push entry for the final figures"), verified by the closeout, swept by the next session's bump. The doctrine: an execution-status section is a ledger, not a scratchpad — every box is either done (checked) or pending (unchecked with future-tense text), and any line that is both is a defect.**
- **A coverage claim is a universal, and a universal needs a SOURCE-side map (session 54: the PAD §7.3 "every pure seam in `src/lib/` is unit-tested" was born true at session 1, went false at session 12 when `route-head.ts` landed with E2E mechanism pins only, and drifted 42 sessions — because the s49 pads map the RUNTIME to §7.1's rows, and a source file with no test never enters the runtime; nothing compared the claim's universal to the fs + the test-import graph. The closure: the explicit MAP (the s41 allow-list pattern — never a naming convention; every entry import-verified by specifier resolution), the fs boundary (a new seam fails loudly until mapped or excluded, the db.ts named-exclusion precedent), and the claim-presence guard (the §7.3 sentence cannot be silently weakened). The doctrine: the tests that EXIST can never prove the tests that are MISSING — every coverage claim needs a map from the source side, held to the fs)**

- **A `~N` size figure is a checkable claim, and its ground truth is one `wc -l` (session 53: the PAD §11 Key Files Reference's 17 line-count figures were born true at the session-1 docs and drifted up to 3.6x stale across 44 sessions — validation.ts claimed ~120 against 437 actual lines, seed.ts ~180 against 83 (the s43 extraction inverted it) — because the session checklist bumps the SKILL frontmatter + the corpus counts, never §11's size figures; the SKILL's compound auth claim drifted the same way ("~170 auditable lines, 11 unit tests" vs 232 + the §7.1-runtime-pinned 20). The class survived every pin family because the SIZE shape matches no corpus-count, §7.1-row, quoted-output, requirements, or date form. The closure: EXACT figures (the `~` hedge dropped — a hedge that can be 3.6x off is not an approximation, it is a stale claim; a +/-20% tolerance band would have passed auth.ts's +36% drift today) pinned to the fs (newline-character counting, `wc -l` semantics — no git history needed, no mtime trap), with the grammar rejecting the tilde form at the extraction level (a malformed row, not an approximation) and the row floor + the seed-data key-coverage guarding the table's shape. The doctrine: audit the docs' SIZE surfaces the way corpus figures are audited against the run; bump the row when the file changes — a size signal that does not move with the file is a stale claim no corpus family will ever catch)**

- Trusting an ORM's "contains" without reading its compiled SQL (session 26: Prisma's SQLite `contains` compiles to a bare `LIKE '%…%'` with NO `ESCAPE` clause — so a user's literal `%`/`_` flowed through as live wildcards and `?search=%` silently returned the ENTIRE unfiltered feed presented as matches, for 24 sessions, on a user-visible surface. - Auditing the request QUERY grammar while leaving the request BODY grammar open (session 32: sessions 24–29 closed the query surface param-family by param-family — pagination, vocabularies, free text, the set, the empty grammars API-wide — while every write route silently accepted any unknown top-level JSON body key: a create carrying `banana:1` stored, a login carrying `banana` logged in, and a create carrying the PATCH route's `status` was accepted with the value ignored. - Auditing the RESPONSE grammar while forgetting the CONTENT TYPE of the residual surfaces (session 33: the query grammar closed s24–s29, the body grammar s32, the response envelopes s32 — while every UNKNOWN /api/** path still served the framework's HTML 404 (content-type text/html), the last non-JSON speaker in a namespace whose every known route spoke JSON on success AND error.
